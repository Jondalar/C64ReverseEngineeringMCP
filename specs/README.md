| 815 | [Turbo/speed registers](../../TRX64/docs/815-turbo-speed-registers.md) | PARTLY BUILT 2026-08-18 | A cartridge release does not ask "am I a C64", it PROBES — `$D031`, then the `$D02F`/`$D030` pair — and takes a different code path when the answer is yes. On a plain C64 every one of those reads is `$FF`, so the whole turbo half of a release (its timing tables, its raster delays) is dead code no amount of playing will reach; a bug living there is not hard to find, it is **unreachable**. Built: the registers with VICE's read-back masks (`vicii-mem.c:960-980` — write `$FE`, both read `$FE`; write `$00`, they differ by exactly `$04` — the masks ARE the detection), an extended `$D031`, and a machine profile `c64` (default, unchanged) / `128` / `u64` as BOTH a parameter (`session/turbo`) and a monitor verb (`turbo`, `turbo mode`, `turbo on\|off`, `turbo speed`). The profile survives a reset: it is machine identity, not chip state. **Deliberately NOT built — §3, and it is the half that matters:** what a SET speed bit does to the picture. VICE models the CPU side (`vicii-clock-stretch.c`) and nothing about the display, which is why the reported fault does not reproduce there either. The hardware observation — bars where text/bitmap should be while COLOUR RAM stays correct — says the addressing is fine and only the main-bus data is wrong, i.e. open bus; but whether the bars are stable or move decides the implementation, and guessing would put behaviour in this emulator that exists nowhere else. Gates: the probe run as the probe, and one asserting the picture is IDENTICAL with the bit set — so §3 stays a visible hole. | 2026-08-18 |

A state anchor heals itself and cannot drift, so the state is the anchor and the cycle budget is the ripcord, at the same step. The load-bearing idea: **a marked screen rectangle is an ADDRESS SET, not a picture crop** — text mode is `$0400+row*40+col`, so a compare runs over bytes, exact and blind to sprites and raster around it, and `vic/inspect/region` already does the translation. A region may be defined locally in the `.feature` OR resolved from the store, local shadows store, and the run SAYS which. One new machine fact in the runtime: `session/read_memory`. Built with it: a fifth copy of the BUG-051 bank formula was hiding in `session/state`, which is why the absolute VIC bases are reported now instead of $D018 offsets every consumer has to add a bank to. The recorder that writes this vocabulary is 814. Gate `npm run smoke:813` (39). | 2026-08-18 |

**READY** = the next step is written down; someone could start tomorrow.

There is no "in progress": nothing here is being worked on, and a status that claims
otherwise is a lie the folder tells every visitor. The date column is the honest version.

Where a spec shipped and only a named part is left, that is said in *What is left* — it
is a fact about the past, not a status. Read those files knowing most of what they
describe already exists, and that changing it risks working code.
