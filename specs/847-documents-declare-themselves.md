# Spec 847 — Documents declare themselves

**Status:** DRAFT
**Branch:** `spec-847-documents-declare`
**Repo:** C64RE
**Origin:** the owner, after asking what became of Spec 740's wiki:

> "Ist das 'Wiki' die richtige Antwort? Oder brauchen wir in den Markdowns Templates mit
> Frontmatter und dann ein JSON-Store neben dem Graphen?"

and, on making it stick:

> "Den Zwang die Erkenntnisse in ein Frontmatter-strukturiertes MD zu legen und dieses zu
> indizieren, das können wir doch aber erzwingen."

## 1. The measurement

Spec 740.1 shipped the wiki skeleton in May. Both long-running projects were checked:

```
Ultima VI     docs/index.md   880 B   7 of 7 categories "(no curated entries yet)"
Neuromancer   docs/index.md   880 B   7 of 7 categories "(no curated entries yet)"
```

Not one line was ever written into either. 740.2 — `project_wiki_update`, the tool that
would have written them — is BACKLOG and does not exist, so the only thing that could
fill the wiki was a human, and no human did.

**But the synthesis was written anyway.** Ultima VI's `docs/` holds `EF_PORT_SPEC.md`
(59 KB), `RAM_BUDGET.md`, `CHEATS.md`, nine model documents under `docs/model/` and a
310 KB HTML. The need was real and the sessions met it. They simply met it in files that
nothing indexes, nothing lints and nothing can cite.

**The wiki was not routed around because it was a wiki.** It was routed around because it
asked for DUPLICATE work with no payoff to whoever did it: the document was already
written, and the wiki wanted a summary of it, somewhere else, for the benefit of a future
reader. That trade loses every time.

Frontmatter has the inverse economy. The document is being written regardless; six lines
at the top cost almost nothing, and they buy the writer an indexed, citable artefact.

## 2. `docs/` currently holds three contracts and shows you none of them

| file | contract |
|---|---|
| `FINDINGS.md`, `ENTITIES.md`, `OPEN_QUESTIONS.md`, `ANTI_PATTERNS.md` | generated by `render_docs`, "do not edit by hand" |
| `index.md` | curated, meant to be written by hand — empty since May |
| `EF_PORT_SPEC.md`, `RAM_BUDGET.md`, `docs/model/*.md` | written by hand, known to nothing |

Nothing distinguishes them but a comment inside the generated ones. A reader — human or
session — cannot tell which of these is authoritative, which is derived, and which is
three days stale. Ultima VI's `FINDINGS.md` renders 19 of that project's 41 findings and
says nothing about it.

## 3. Decisions

**D1 — The rule, and it demands no new documents.**

> Every synthesis document that exists declares what it covers, and what it covers
> resolves in the graph.

Not "every finding must also be prose" — that is the wiki's doubling trap again. The
finding is already in the graph with its evidence. What belongs in prose is the
SYNTHESIS: the argued narrative the graph structurally cannot hold. This rule turns
documents that are already being written from orphans into nodes.

**D2 — Frontmatter is the declaration.** YAML at the top, small enough to be written by
hand without resentment:

The fields are not invented. They are what these documents ALREADY say, in prose, in
their own opening paragraph. Ultima VI's `A_overlay_model.md` begins:

> Static analysis only. Every address below was read out of `07_game.prg` (load `$0200`,
> 16767 bytes, spans **$0200-$437E**) […] Where the rendered listing and the binary could
> disagree, **the binary wins**: all "every store to X" claims come from an exhaustive
> opcode scan of the 16767 bytes, not from grepping the `.asm`.
> Sources: `07_game.asm` / `.sym` / `.prg`, `u6_ovl_c000_t{3,4,5}.prg`, …

That is `covers`, `sources`, and — in the middle — **the evidence standard, per document**.
Spec 844 made S13 a project-level slot; at document level it is sharper, and a session
wrote it there unprompted.

```yaml
---
title: The engine's overlay / resource model
kind: synthesis            # synthesis | reference | generated | decision
covers:
  - $0200-$437E            # address ranges this document explains
  - artifact:07_game.prg
sources: [07_game.asm, u6_ovl_c000_t3.prg]
method: >
  Static analysis only; where listing and binary disagree the binary wins.
  Every "all stores to X" claim is an exhaustive opcode scan, not a grep.
amends: A_overlay_model.md # what it corrects, if anything
status: current            # current | superseded
---
```

`claims: [F-3312]` was in the first draft and is dropped: **not one document in any
project names a finding id.** By this spec's own rule a field nobody fills is worse than
no field, because it makes the declaration look complete.

**D3 — A document is a node, not a second store.** The owner's own question asked whether
a JSON store should sit next to the graph; it should not. Spec 822.2 removed exactly that
arrangement, and `DOCTRINE.md` records why: three copies drifted. Frontmatter is INDEXED
into the graph — a `document` node with the ranges it covers and edges to what it cites.
Then Spec 845's boundaries can cite a document, and Spec 846's `amends:` resolves instead
of being a free string that points nowhere.

**D4 — Generated documents carry their provenance, so staleness becomes computable.**
`render_docs` writes `kind: generated`, the graph revision it rendered from, and the
record count. A check then compares that against the live graph, which is the whole of
the `FINDINGS.md` defect: 19 of 41, three days old, silent.

This also fixes a defect in the search index. It indexes the graph record AND its rendered
Markdown copy, so a stale render puts a second, older version of the same fact into the
results. `rankHints.stale` exists but is only ever set from artifact VERSION status —
never from "this render is older than the graph".

**D5 — A citation that does not resolve is a finding.** `amends: A_overlay_model.md`
where that document is not indexed is a dangling citation. Ultima VI has six refutations
naming documents and not one of those names resolves to anything today. This is Spec 846's
eighth check, and it is the same shape as the negative-claim detector: cheap, decidable,
and it carries the name that failed to resolve as its own proof.

**D6 — The wiki index is DERIVED.** Once documents declare themselves, the index is a
query over them, rendered on read like `model_read` and `project_slots`. It cannot sit
empty for four months, because nobody maintains it. `project_wiki_lint` stops comparing
the first 24 characters of a title with `includes()` — which is guessing — and starts
comparing declared coverage against the graph, which is knowledge. Spec 740.2 is thereby
answered rather than built: the tool that would have written the wiki is not needed.

**D7 — Enforcement lives in the tools; a hook is a second layer, never the first.**

The owner asked whether a hook on the write itself could enforce this — a grant
mechanism. It can, and it must not be the primary layer, for one reason: **a hook lives in
the harness, and the harness is not the product.** A `PreToolUse` hook works in Claude
Code, for one user, when configured. Codex gets nothing, CI gets nothing, and a project
handed to someone else carries none of it.

So the enforcement is layered:

| layer | what | works where |
|---|---|---|
| the critic (846) | undeclared document, dangling citation, stale render | everywhere |
| the verdict (846 D4) | not ready while synthesis documents are undeclared | everywhere |
| `doc_register` | reads the frontmatter, makes the node, links the ranges | everywhere |
| a write hook | refuses the write and hands back the template | Claude Code only |

And the piece that makes the hook worth having: the LOGIC does not live in the hook. A
CLI entry — `c64re doc lint <path>` — holds it, the hook is three lines that call it, and
the same command is available to a different harness, a pre-commit hook, or a person. The
trigger is per-harness; the rule travels with the project.

The hook's shape matters too. Not block/allow: it refuses and returns the frontmatter
template for that document kind, so the fix is one edit away. That is the Spec 834
pattern — refuse and say exactly what is missing — applied at the file boundary.

## 4. Settled by looking rather than asked

Both of this spec's open points turned out to be answerable from the projects themselves.

**The field set** is above: it mirrors what the documents already write in prose, minus
`claims`, which nothing anywhere writes.

**Where documents live.** `docs/`, but not only the top one. Wasteland_EF has 148 Markdown
files, 108 of them "outside `docs/`" — and every one of those sits in a NESTED docs
directory (`cart_EF/docs/engine`, `editor/docs`, `cart_EF/docs/port`). The rule is
therefore any `docs/` directory in the project tree, not the project's own.

Two facts for the build to plan against: no project document anywhere carries frontmatter
today (the only YAML headers in the corpus belong to `.claude/skills`), so every existing
document is undeclared on day one — the check must report a backlog without it reading as
a catastrophe. And Ultima VI's nine model documents are the ones worth declaring first;
they are the corpus's best synthesis and its most invisible.

## 5. Not in this spec

- Writing anyone's synthesis. Nothing here generates prose, and the evidence is that
  sessions write it unprompted — they just write it invisibly.
- Spec 740.2 as originally scoped. D6 answers the need a different way.
- Replacing `render_docs`. It keeps rendering; it just stops lying about how old it is.
